Troubleshooting

Diagnose and fix the most common issues.

502 Bad Gateway

Traefik can't reach the socat container. Work through this checklist:

# 1. Is the socat container running on VPS?
docker ps | grep socat

# 2. Can Traefik reach socat? (must share 'proxy' network)
docker network inspect proxy | grep -A3 socat

# 3. Can VPS reach home through WireGuard?
curl -v http://10.8.0.2:<port>

# 4. Is WireGuard up?
sudo wg show

# 5. Is the app running on home server?
curl http://127.0.0.1:<port>
CauseFix
socat not on proxy networkAdd networks: [proxy] to VPS socat service
Wrong bind on home socatMust be bind=10.8.0.2 + network_mode: host
App container not runningdocker compose up -d on home server
Wrong port in dynamic.ymlPort in Traefik config must match socat LISTEN port

WireGuard Tunnel Drops

🔴 CGNAT — most common cause Missing or too-high PersistentKeepalive on the home server. CGNAT NAT mappings expire in ~60–120s. Set PersistentKeepalive = 25. 
# Check last handshake — if > 3 min ago, tunnel is dead
sudo wg show

# Force reconnect
wg-quick down wg0 && wg-quick up wg0

# Check keepalive config
grep -i keepalive /etc/wireguard/wg0.conf
# Must show: PersistentKeepalive = 25

Game Server Unreachable

# Is the port open on the VPS?
nc -zv <VPS_IP> 25565

# Does DNS resolve to VPS IP (not Cloudflare)?
dig mc.example.com

# Is UFW allowing the port?
sudo ufw status | grep 25565
⚠️ DNS must be grey cloud Game servers need a direct connection. Cloudflare's proxy only supports HTTP/HTTPS. Set the DNS record to DNS only (grey cloud).

Can't SSH After Hardening

# SSH port is now 2222 after running harden-vps.sh
ssh -p 2222 user@<VPS_IP>

# If locked out, use VPS provider's console (Hetzner/DigitalOcean web console)
# Then check:
sudo ufw status
sudo systemctl status sshd
cat /etc/ssh/sshd_config | grep Port

Docker Issues

# Check active daemon config
docker info | grep -E "Storage Driver|Logging Driver|Cgroup"

# Daemon logs
journalctl -u docker.service --tail 50

# Live resource usage
docker stats --no-stream

# Container won't start — check logs
docker logs <container_name> --tail 50
